# PR #4 / 0.8.6-rc.1 发布计划

> 历史记录：对应 2026-09-07 已发布的 rc.1，不是下一版执行清单。当前版本选择见 [README](../../../README.zh-CN.md)，本轮 RC 发布约定见 [开发指南](../../development.md)。

## 目标与口径

- PR#4 适配 dsh 0.1.2-rc.1，并以 0.8.6-rc.1 发布。
- 旧 dsh 0.1.1-rc.2 不要求运行功能，但必须在安装或启动阶段给出明确、可断言的不兼容诊断，不能只报模块缺失或 TypeError。
- 新 dsh 0.1.2-rc.1 必须通过宿主端、客户端、真实 Cordis 挂载、Web 客户端加载、自有 RPC 与模型发现检查。
- 未发布 tarball 先完成隔离测试；通过后合并；只从合并提交打 v0.8.6-rc.1 并发布 npm next。

## 修改边界

- `package.json`、`package-lock.json`：候选版本与最低宿主接口版本。
- `src/index.ts` 及生成的 `lib/*`：必要的旧宿主明确诊断，避免 ESM 链接阶段出现晦涩缺包错误。
- `test/*`：先加入旧宿主拒绝回归测试，再做实现。
- `.github/workflows/ci.yml`：真实启动检查使用 dsh 0.1.2 输出的带 token URL。
- `README.md`、`README.zh-CN.md`、`DESIGN.md`：准确记录支持边界与升级方法。

## 发布前检查

1. 保留已通过的原始基线：`npm run typecheck && npm test`。
2. 复现远端 boot 失败；根因是 CI 请求无 token 根 URL，新 dsh 启动日志只暴露带 token URL。
3. 修复真实启动检查：从日志提取 URL，访问页面，确认客户端加载清单包含插件，并确认 RPC 路由可用。
4. 为旧宿主拒绝先写失败测试；再添加最小兼容性探针与清晰错误。
5. 更新版本为 0.8.6-rc.1，构建并确认提交产物无漂移。
6. 运行 `npm run typecheck && npm run build && git diff --exit-code -- lib/ && npm test && npm pack`。
7. 在隔离 DSH_HOME 中测试旧 dsh 0.1.1-rc.2 的明确拒绝。
8. 在另一隔离 DSH_HOME 中测试新 dsh 0.1.2-rc.1 的完整启动、客户端加载清单、RPC 和模型发现。发布检查不依赖真实外部 API，网关行为由仓库中的测试替身覆盖。
9. 推送到 PR head，等待 build、plugin-check、boot 全绿。
10. 核对 PR head SHA 后合并；核对 main 合并 SHA 后创建 v0.8.6-rc.1。
11. 等待标签 CI 与 release job 全绿；验证 GitHub prerelease、npm next、npm latest 未被 RC 覆盖、发布 tarball 版本和内容。

## 停止条件

任一构建、测试、PR CI 或双环境检查失败，都应停止合并或发布；定位并修复原因后，重新执行受影响的检查。
