# dsh 0.1.5-rc.1 适配与版本合并评估

核对日期：2026-09-10。仓库基线：main `e6e23bf`；上游固定标签：`dsh-v0.1.5-rc.1`。

## 结论

可以将本次适配与已有 0.8.6 候选发布线合并，建议下一版为 **0.8.6-rc.2**。无需退回 0.8.4 重做此前适配，也没有待合入的 0.8.6 分支：PR #4 已合入 main，当前远端开放 PR 数为 0。

但不应覆盖 v0.8.6-rc.1，也不建议现在直接晋升 0.8.6 正式版。rc.1 已于 2026-09-07 发布至 GitHub Pre-release 和 npm next；新宿主上的完整安装、Web 启动和浏览器联调尚未验证。当前评估只能确认类型、构建、现有组件测试和 Cordis 组合测试兼容，还没有完成全部发布前检查。

| Session V3 / Agent API | 插件没有直接读写 Session 日志、访问 ctx.agent 或实现 Inbox。未发现需要跟随这些破坏性变更改动的调用点。宿主升级后的会话降级限制仍属于上游迁移约束。 |

### 必须处理的依赖声明问题

当前 peerDependencies 使用 `>=0.1.2-rc.1`。用本机 npm 内置 semver 实测：

```text
satisfies('0.1.2-rc.1', '>=0.1.2-rc.1') = true
satisfies('0.1.5-rc.1', '>=0.1.2-rc.1') = false
satisfies('0.1.5',      '>=0.1.2-rc.1') = true
```

npm 范围不会自动接纳另一个版本核心的 prerelease；而源码最低版本 guard 的自行比较会接受 0.1.5-rc.1，造成声明与运行时判断不一致。适配不能只改 devDependencies。

建议明确选择支持策略：保留旧版覆盖时，peer 范围显式包括 `0.1.2-rc.1` 和 `0.1.5-rc.1`，CI 验证两组固定版本；如接受相应补丁线后续正式版本，可用 `>=0.1.2-rc.1 <0.1.3 || >=0.1.5-rc.1 <0.1.6`，但不得将范围内所有版本都写成“已验证”。宿主版本 guard 的文案与范围应同步审视。

在隔离目录 `.verify/compat-015` 中复制当前源码，将所有 dsh 开发依赖和已有的替代依赖统一切换到 0.1.5-rc.1，再安装 npm 实际发布的包。为避免一次改变太多条件，本次测试保留了原有 overrides；这不代表新版本仍然需要它们，正式升级依赖时应逐项核查。

| Cordis smoke | 通过 | 通过 |
| 新版真实 dsh web / 安装 tarball / 浏览器联调 | 本轮未运行 | 尚未运行 |

组合测试使用真实 Cordis、LlmRuntime 和 SettingsProvider 的内存实现，网关请求和凭据由测试替身提供。它不能代替真实浏览器或远端网关联调。由于本地没有 models.dev 缓存，本轮跳过了真实目录检查；可选的宿主接口快照一致性检查也没有运行。

上游源码归档已读取；Windows 解包时有若干符号链接无法创建，相关 LLM、settings、connection、代理源文件可正常读取。关键接口另以真实发布 npm 包的类型检查与测试验证。

适配评估阶段唯一已有文件改动是 `test/host-compat.mjs`：两处子进程动态 import 改用 `pathToFileURL(...).href`，修复 Windows 把盘符识别为 URL scheme 的失败。该阶段未改动主仓库业务代码、package.json、lockfile、lib 和发布配置。后续文档整理已重写 README 与设计说明、新增配置和开发指南，并将 docs 加入包的分发清单；包版本仍为 0.8.6-rc.1。

## 建议实施步骤与合入条件

1. 从当前 main 开始，将包版本更新为 0.8.6-rc.2；保留 rc.1 标签和 npm 包。
2. 升级开发依赖和锁文件，在 peerDependencies 中明确支持新 RC，并重新检查 overrides 是否仍有必要；补充 0.1.5-rc.1 导出快照，保留旧宿主拒绝检查。
3. CI 固定目标为 0.1.5-rc.1；若保留 0.1.2-rc.1 支持，则同时覆盖两组宿主，而非只凭最低版本 guard 放行。
4. 更新双语兼容表、代理行为及失败提示；按需求另行决定 totalTokens、图片和动态系统提示词能力，不与最低兼容要求混淆。
5. 完成构建、类型检查、现有测试、产物一致性检查、打包自包含检查和插件规范检查。使用同一个待发布 tarball，在隔离的 DSH_HOME 中验证 Web 认证启动、客户端加载清单、自有 RPC、模型发现、设置与凭据保存，以及浏览器中的实际设置页；再用本地网关验证文本流、工具调用与取消。
6. 所有必需检查通过后，合入 main 并将 v0.8.6-rc.2 发布到 npm next，同时在 GitHub 标记为 Pre-release。本轮明确不晋升正式版，npm 与 Git latest 保持 0.8.4；未来是否发布正式版另行决定。

**合并判定：可以合并到同一候选发布线；目前证据不支持直接正式发布。**
